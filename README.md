# 轮舞于星辉尽头 · PixelRogue

基于 **Godot 4.7.2** 的俯视角房间探索与动作肉鸽游戏，支持 Windows 与 Android。当前版本为 **V0.56**；更新三角色手绘模型、营地居民、首领动作与高清特效、剧情阅读和成长界面。初始房间已恢复原静态精细像素地图，动画试验关闭。用户授权本批上传Git并导出Windows／Android发行包，结果见[交接29.36](docs/CODEX_HANDOFF.md)。

营地只保留训练场入口。进入独立的「星辉演武场」后，可以打桩查看DPS、调整训练等级／天赋、临时试穿或切换技能；设置面板和顶部按钮均可返回营地。返回时恢复原来的正式配装与准备草稿，训练不消耗仓库库存、金币，也不创建出征。营地的天赋快捷键转到配装技能页；独立训练地图内仍打开训练天赋。

## 启动工程

1. 安装 Godot 4.7.2，克隆本仓库。
2. 在 Godot 项目管理器中导入根目录的 `project.godot`。
3. 等待首次资源导入完成，按 **F5** 启动。

默认入口为 `src/main/game_shell.tscn`，由它进入主菜单、选人、营地及正式冒险。当前使用 Compatibility 渲染器。

命令行启动：

```powershell
godot --path .
```

源码运行会使用正式玩家存档。自动化测试应使用独立测试环境，不要用真实存档初始化测试角色、仓库或出征。

## 游戏内 Bot 测试

编辑器或 Debug 构建中，正常进入冒险后按 **B** 启动 Bot；再次按 **B** 或点击底部提示旁的 **×** 停止，同一局可反复启停。也可按 Esc 打开暂停菜单，点击“Bot 测试／停止 Bot”。使用当前角色、装备、技能、种子和难度，复用已有的自动战斗、拾取、配装、加点、奖励选择与切房逻辑，不额外提供属性或物资；死亡损失、成功撤离入库规则保持。

Bot 战斗中会使用已有的治疗、回蓝、伤痕修复及增益药剂；相同属性的有效增益不会反复喝药覆盖。需要且材料足够时，优先前往可到达的商店／酒馆安全房，通过战地炼金补货，保留委托与工坊目标所需材料。不会在未清战斗房远程制作，不消耗历史仓库、不自动研究配方或购买商品。安全房通常备至两瓶治疗、两瓶回蓝、各一瓶已解锁增益，实际受材料、背包和难度规则限制；浴血不制作或使用普通治疗。

Bot 会前往未完成且未坍塌的祭坛，先领取原有房间奖励，再实际靠近祭坛、预览并确认可选塔罗；优先考虑角色共鸣、伤痕修复与当前生存需求。占卜次数、正逆位、保存与跨阶段继承沿用正式规则，不重抽牌。制作或缔结保存失败会回滚并暂缓重试，避免卡在界面连续提交。

快捷键启动前先关闭对话／背包等界面，并等待切房、接引结束；这些过程中仍可停止已经运行的 Bot。暂停菜单按钮会先关闭暂停再启动。营地和独立训练场不启动冒险 Bot。Release 构建默认关闭快捷入口，显式使用 `--bot-test` 启用，例如 `godot --path . -- --bot-test`；本批没有重新打包。

F9 保留给 Godot 编辑器的内嵌游戏挂起／恢复，已不用于 Bot。原生挂起期间不直接修改 SceneTree 暂停状态；退出清理使用不受挂起缩放时间影响的计时，保存失败仍保留本局并允许重试。

入口脚本为 `src/room_mode/bot_test_control.gd`，已由冒险场景自动挂载，不需手动添加。测试入口保留本局已使用 GM 的记录，原彩票彩蛋仍每局一次；没有新增存档字段。操作日志输出到 Godot 控制台，详情见交接文档第24节。

## 材料与工坊

局内商店和酒馆顶部的「炼金与刻印」使用本局背包材料。治疗、回蓝与星露复生剂配方默认开放，其余配方可在营地仓库或与布琳娜交互时研究。每个装备部位最多一个刻印，仅本次出征有效，卸下后停止生效，替换前显示原效果与费用；刻印冷却与待消耗状态随出征保存。浴血不能制作普通治疗药剂；星露复生剂仍可修复完整生命上限25%的实际伤痕，并返还等量生命，不占塔罗每房修复额度，没有伤痕时不会消耗。

工坊支持按名称或材料搜索，以及全部、已解锁、当前可操作筛选。药剂可一次制作1—10份，提交前列出总量、保留量、可用量、总消耗与剩余量；整批保存失败会完整回滚。材料详情可展开全部配方用途，仓库能直接打开相关配方。出发准备可前往仓库或工坊再返回原清单，空装备槽和未携带药剂仅作提醒；材料结算按类别汇总，可展开明细并查看可进行的研究和委托。

营地「制作与研究」使用永久仓库材料，研究全角色共享；定向制作的装备视为绑定装备。可设置一个研究目标，默认保留委托与该目标需要的材料；取消保留后可主动用于制作。原有商店产出保持开放，不因研究而反向锁定装备；原蘑菇兑换改用金币或特殊材料。

成功撤离即可带回未消耗材料，无需先通关整章；终章素材深渊根心、无名星核仅由对应最终首领产出，所有首领素材均不能购买、出售或用普通材料兑换。普通首领固定一份，BossRush沿用双倍奖励。普通战斗房若未产出材料，清理时补发一份当地常见素材，每房只结算一次。死亡仅损失本局携带材料，历史仓库不受影响；结算显示收集、消耗、带回、首次发现与可处理的研究和委托。

## 浏览器开发工作台

地图编辑、图层透明边缘精修、界面文案／按钮布局、物资控制台与单位数值统一在本机浏览器打开。现有 `RoomEditor.cmd` 启动文件和 `tools/room_editor/room_editor.tscn` 入口均会打开浏览器工作台。服务仅监听 `127.0.0.1`，不上传工程数据；右上角可以关闭服务。

```powershell
godot --path . res://tools/room_editor/room_editor.tscn -- --room-editor
```

支持地图图层查看、实际碰撞轮廓、外边界、四向出口、出生点和营地设施交互点编辑，以及游戏内验证。验证结果供参考，不阻止开发者保存模板。

页签可直接切换各开发工具。地图保留图层显示、缩放平移、碰撞顶点／矩形、外边界、四门、出生及营地交互点、光源、撤销重做、JSON导入导出和独立游戏验证。存入模板池同时同步正式工程的同ID模板，避免后续导出仍使用旧地图；已有校验提示不阻止保存。多个窗口编辑同一份数据时会检查版本，拒绝静默覆盖。

图层精修保留底图只读；擦除／恢复只改透明度，保留图片原尺寸与颜色。历史原始图层、发放存档的备份均保存在工程外。物资控制台需要手动载入目标存档并确认发放；修改前应关闭使用该存档的游戏。单位数值保存至 `data/unit_balance.json`，支持恢复默认，新启动游戏后生效。开发工具不进入玩家发行包。

也可以直接启动（Python需安装Pillow以使用透明边缘精修，本机启动文件已使用带有该库的运行时）：

```powershell
python tools/browser_tools/server.py --project . --godot "Godot可执行文件的绝对路径"
```

`--native-room-editor` 仅保留给旧工具回归测试。日常使用浏览器工作台。

营地内按当前绑定的地图键（默认 M）查看实际建筑模型、自己、设施和移动 NPC 的位置与名称。背包管理正式出征配装，仓库负责物资整理；独立训练入口进入另一张地图。营地商店购买的装备均为绑定装备，成功撤离后原件返回仓库，战斗死亡仍会损失。

- 内置模板：`assets/room_templates/`。
- 分层场景与运行素材：`assets/room_illustrated/`。
- 开发者保存的自定义模板位于 Godot 用户目录的 `room_templates/` 中，默认优先于同 ID 内置模板。
- 发行前应核对自定义营地模板是否已同步到内置模板；`tools/sync_authoring_templates.py` 提供同步工具，执行前先检查其目标路径。

地图编辑器属于开发工具，不随玩家发行包导出。

## 导出玩家版本

`export_presets.cfg` 包含当前 Windows 和 Android 发行预设。自定义模板、SDK、Java 与签名密钥是本机配置，克隆后需在 Godot 导出设置中配置；私钥和密码不属于仓库内容。

导出前核对版本号、章节素材、最新营地模板和资源引用，使用 Release 模板。玩家包排除地图编辑器、测试、制作工具、原稿和文档；规则由导出预设及 `tools/audit_player_export.py` 维护。

```powershell
python tools/audit_player_export.py
```

上述命令只检查资源；添加 `--apply` 才会更新排除规则。导出后应运行 PC 冒烟检查，并校验 Android 的版本、签名和包完整性。
