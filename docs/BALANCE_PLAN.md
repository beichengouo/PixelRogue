# 数值平衡计划（BALANCE_PLAN.md）

> 这份文档是"平衡实验室"的 Phase 0 审计 + 校准记录。
> 工具在 `tools/balance_lab.gd`，跑法见文末。数值改了以后重跑一次就是新结论。

## 一、抽象模型映射（Phase 0）

| 抽象概念 | 本作对应 | 备注 |
|---|---|---|
| Session | 一局（第 1 波 → 第 100 波） | 中途死亡即结束 |
| Threat | 全场怪物的血量池 + 贴身接触伤害 + 精英词条 | |
| Defense / agency | 玩家 DPS（等级 / 天赋 / 装备 / 技能）、最大生命、升级回血、商店回血 | |
| Faults | 同时在线怪数、屏外刷新、精英词条 | |
| Resources | 魔法值（技能闸门）、金币（商店）、钥匙（宝箱） | |
| In-run economy | 击杀金币 + 波次奖励 → 商店物价（每波 +6%） | |
| Meta economy | 无（本作是单局肉鸽，不做跨局货币） | |
| Grade | 到达波次（100 = 通关） | |

**主指标**：整局通关率（按玩法分档）。

## 二、目标区间（覆盖默认值）

原始 skill 的默认区间是给"关卡制动作游戏"用的（casual 55~90%）。
本作是**一局 100 波的永久死亡肉鸽**，菜鸟本来就该死在前中期，所以覆盖为：

| 玩法 | 通关率目标 | 含义 |
|---|---|---|
| afk | 0 ~ 5% | 完全不动，必然死 |
| casual | 0 ~ 15% | 会打但不会走位，死在中前期 |
| average | 10 ~ 45% | 普通玩家，死在中后期 |
| pro | 40 ~ 85% | 熟练玩家，多数能通关但不该稳过 |

## 三、模型（公式化，零手抄）

模拟全程驱动**游戏自己的代码**，不复制一份数值：

- `WaveTable.build(wave)` → 这一波的怪数、血量/伤害/速度/出手倍率
- `WaveDirector.create_enemy(kind)` → 每种怪的基础血量 / 伤害 / 金币
- `GameState.new_run()` / `gain_exp()` / `spend_talent_point()` / `_reset_stats()`
  → 等级、天赋树前置条件、装备与遗物的属性结算**全部是游戏真实逻辑**
- `Skills.get_skill(id)` / `GameState.learned_skills` → 技能伤害与耗蓝
- `EnemyAffixes.roll_for_wave(wave, rng)` → 精英词条条数（采样 40 次取期望）
- `ItemDB.all()` → 商店可买的道具与价格

模型里唯一"自定"的是**人的部分**（每种玩法射击命中率、有效输出时间、挨打频率），
这些无法从源码提取，只能校准——见下一节。

## 四、Phase 7 校准（黄金格）

1. **无头 bot 试玩实测**（`--autoplay`）：
   - 第 2 波掉约 27 血、第 3 波掉约 50 血、第 4 波掉到 9/172 后阵亡
   - 换算成"每秒被打中次数"≈ 0.2 次/秒（bot 是"会打不会躲"的水平）
2. **玩家实测反馈**：前期几乎碰不到人、不买商店也能轻松过 → 真人挨打频率远低于理论值

两条合起来说明：**每个敌人各自结算接触伤害是错的**——玩家有 0.75 秒无敌帧，
同时贴多少个敌人也不会线性叠伤害。模型改成"每秒被命中次数（上限 1/0.75）× 暴露时间"，
再用整体系数校准。扫描结果：

| contact_scale | casual | average | pro |
|---|---|---|---|
| 0.6 | 0% | 0% | 75% |
| 0.4 | 0% | 0% | 100% |
| 0.25（采用） | 0% | 0% | ~100% |
| 0.15 | 0% | 100% | 100% |

取 0.25 作为默认锚点，并把扫描开关保留成 `--contact_scale=`，方便以后重新对齐。

## 五、本轮发现与改动

### 发现 1：等级曲线在第 30 波就封顶（已改）

- 现象：`exp_needed = 10 + 4·L^1.35`，而"每杀一只怪的经验"还会随波次线性上涨
  （`12 + wave×2`）。两者相乘 → 第 10 波 32 级、第 30 波满 100 级。
- 后果：后面 70 波**完全没有成长**，连升级回血都一起消失；天赋点早就点满。
- 改动：
  - `game_state.exp_needed` → `12 + 3.2·L^1.85`
  - `main.gd` 每杀经验 → 固定 `14 × 倍率`（不再随波次上涨）
- 校准后：第 10 波 16 级、第 30 波 39 级、第 50 波 57 级、第 70 波 72 级、第 100 波 93 级。
  真实游戏里 bot 在第 3 波的等级从 10 级降到 7 级，与模型一致。

### 发现 2：后期清场时间会爆炸成"磨血"（已改）

- 现象：血量倍率是 `1 + 0.34·step + 0.045·step²`，第 100 波 = 475 倍；
  而一波的怪数从 6 只涨到 600 只（100 倍）。两者相乘，第 50 波单波要 177 秒。
- 改动：二次项压到 `0.018`（第 10 波 ×5、第 30 波 ×21、第 50 波 ×47、第 100 波 ×153），
  难度改由**数量、精英词条、Boss**承担。
- 改动后：pro 的清场时间曲线 3.1s → 21.7s → 49s → 78s → 134s（第 10/30/50/70/100 波），
  不再是 177 秒起步的磨血。

### 发现 3：精英词条的压力不随波次增长（已改）

- 现象：`roll_for_wave` 在第 10 波之后概率完全固定，第 50 波和第 10 波的精英分布一模一样。
- 改动：词条条数按波次分层——第 25 波起基础 2 条，第 50 波起 2~4 条，第 75 波起 3~5 条。
  "重创（按玩家最大生命百分比掉血）"这类专门反制堆血堆输出的词条因此在中后期才真正出现。
- 效果：pro 通关率从 100% 降到 95%。

## 六、仍然存在的偏差（留给下一步决策）

跑 `--runs=300`（contact_scale 0.25）的结论：

| 玩法 | 通关率 | 95% CI | 目标 | 判定 |
|---|---|---|---|---|
| afk | 0.0% | 0.0~1.3 | 0~5 | OK |
| casual | 0.0% | 0.0~1.3 | 0~15 | OK（中位到达第 33 波） |
| average | 0.0% | 0.0~1.3 | 10~45 | TOO_HARD（中位第 56 波） |
| pro | 99.7% | 98.1~99.9 | 40~85 | TOO_EASY |

**最值得注意的结论：本作现在的胜负几乎完全由"玩家会不会被打到"决定，而不是 DPS 够不够。**
熟练玩家一旦掌握走位与无敌帧，中后期几乎不掉血，所以"不买商店也能通关"是成立的。

想把 pro 从 ~100% 拉进 40~85%，正确的方向是**加压**而不是加血：

1. 远程/瞬移类词条的出现频率（现在靠词条总数间接提升，可以再单独加权）
2. 弹幕密度与飞行速度（咒术师三连扇形弹幕的覆盖）
3. Boss 的场地机制（第 30/60/100 波）
4. 玩家的**回血节奏**（升级回血 15% + 商店休息 30 是"打不死"的主要来源之一）

反过来，如果觉得 average 死在第 56 波太早，就调低 `damage_scale` 的斜率
（现在是 `1 + 0.12·step`，第 100 波 12.9 倍）。

## 七、怎么跑

```powershell
# 全量（4 档 × 300 局）
Godot_v4.7.2-stable_win64_console.exe --headless --path . --quit-after 4000 tools/balance_lab.tscn -- --runs=300

# 只跑两档 / 改校准锚点
... tools/balance_lab.tscn -- --runs=200 --styles=average,pro --contact_scale=0.3
```

每次跑完会在 `docs/balance/` 写一份 `snapshot_*.json`，可以拿两份做对比。
